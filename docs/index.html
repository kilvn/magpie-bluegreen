要解决什么问题

不是「怎么升级」，而是「升级时正在跑的请求怎么办」。

✕ 手动升级

  • docker pull + compose up -d 直接重建
  • 正在传输的流式响应被切断
  • 跑了几分钟的推理任务归零
  • 被掐断的请求连用量都不写——看起来像少了几次调用

✓ 蓝绿升级

  • 新版本先在旁路端口完整验证
  • 验证通过才把流量切过去
  • 旧容器按实际连接数退役，长请求跑完再收
  • 任何一步失败自动回滚，线上始终有可用版本

两种容器模式

脚本自己看容器是谁起的，不需要你告诉它。

compose 模式docker 模式
判定依据容器带 com.docker.compose.* 标签无 compose 标签
重建方式compose up -d --force-recreateinspect 反推端口/环境/挂载/entrypoint 后 docker run
现有编排零改动零改动（容器怎么起的都能接管）
升级窗口配了 VHOST = 零停机；未配 = 原位重建 1–2 秒

两种模式共用同一套蓝绿逻辑，差异只在「怎么重建容器」这一个动作上。docker 模式的参数不靠猜，全部来自运行中容器的真实规格，所以重建结果与原容器等价。

安装与使用

curl -fsSLO https://raw.githubusercontent.com/kilvn/magpie-bluegreen/master/magpie.sh
chmod +x magpie.sh

sudo ./magpie.sh          # 交互菜单

菜单：

1) 状态            当前版本 / 是否有待部署更新
2) 检查并升级      一次完整蓝绿流程（无新版则秒退）
3) 强制演练        FORCE=1，镜像未变也走一遍
4) 查看日志        最近 40 行
5) 清理对话        保留 N 天
6) 导出样例        nginx / 客户端接入片段
7) 编辑配置        /etc/magpie-upgrade.env
8) 安装定时任务    每 10 分钟升级 + 每天 04:35 清理
9) 卸载定时任务

命令行调用（适合 cron，无 TTY 时菜单自动降级为帮助）：

magpie.sh --status          # 状态快照，只读
magpie.sh --upgrade         # 检查并升级（无新版秒退）
magpie.sh --retention 30    # 清理 30 天前的对话
magpie.sh --logs 100        # 最近 100 行日志
magpie.sh --export ./out    # 导出 nginx / 客户端样例

配置

三级优先级：环境变量 > 配置文件 > 内置默认值。默认读 /etc/magpie-upgrade.env。

大部分不用配——容器名、端口绑定、/config 数据目录、网络、启动命令全部自动探测。真正需要决定的只有：

变量作用默认
VHOST反代 conf 路径。配了 = 零停机 proxy 模式空（direct）
PUBLIC_HOST反代探活时的 Host 头空
DRAIN退役最长等待秒数700
RUNTIME_DIRMCP 运行时目录。空 = 跳过检查空
GATEWAY_KEY业务探测密钥。空 = 从 caller-keys.json 提取空
KEEP_DAYS对话保留天数30
SKIP_PULL1 = 不拉取，直接用本地镜像0
FORCE1 = 镜像未变也强制走一遍0

五个关键设计

1 · 状态合并不做白名单

凡临时容器副本里比线上新的文件都并回，只跳过锁与备份文件。

为什么：上游新增状态文件时，固定清单跟不上，会把对话记录、掩码表整段丢掉。JSON 先校验再原子替换，providers.json 另加供应商数量下限校验。

2 · 追加型数据直接共享

用量、路由、对话、脱敏、签名不复制也不合并，两个容器 bind mount 同一份。

为什么：对同一文件 O_APPEND 追加是原子的，既不会丢也不会重。复制反而会在窗口期漏记。

3 · 坏镜像只试一次

失败记忆 + 退避：同一镜像 30 分钟内不重建，累计 12 次后停止，上游出新镜像自动解除。

为什么：否则坏版本每 10 分钟白复制几百 MB 配置，一天能写满磁盘。

4 · 退役按连接数自适应

每 5 秒采样退役容器的 ESTABLISHED 连接数，清空立即收尾，否则等满 DRAIN。

为什么：固定 120 秒会掐断 p99.9 那批请求，而它们恰恰是最贵的推理调用。

5 · 合并点卡在「重建之后、就绪之前」

此刻旧进程已经停止，不会出现旧版本读到新版本迁移过的配置（降级损坏）；新容器还在启动，来得及拿到临时容器刷新过的 token。

这是个很窄的窗口，但两侧都是错的：合并早了会降级污染，合并晚了新容器已经读完配置。

边界与取舍

场景行为
无反代（direct 模式）切换窗口 1–2 秒。要零停机请配 VHOST
常驻 SSE 连接不释放等满 DRAIN 后照常收尾，不无限等待
升级途中断电 / 被 kill下次运行自动收敛到一致状态，不需要手工介入
